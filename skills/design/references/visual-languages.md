# Visual languages

A visual language is a named physical or cultural object that the screen behaves like: a wine
list, a timetable, a field guide. The name gives you the type, the grid, the texture and even
the UI words. Without a name, every decision falls back to the default.

Use this file in step 4 of the skill, for a new product or a new key screen. A product with a
house style already has its language. Do not replace it.

## 1. How to find one

1. Read the idea sentence and the 8 to 12 details in `DESIGN.md`.
2. List the objects the subject already touches. A bakery has signs, paper bags and
   chalkboards. A festival has wristbands, timetables and posters. A logistics tool has
   waybills, dock boards and pallet labels.
3. Derive a language from that list first. Use the catalogue in section 3 only after that.
4. Test: you can describe the screen in three words without "modern", "clean", "sleek" or
   "minimal".
5. Do not pick a language used on the last 2 projects. Write the language in `DESIGN.md` so the
   next project can see it.

## 2. Rules for any language

- Execute one language precisely. Do not mix two.
- Derive the parts from it, and write each part in `DESIGN.md`. Examples: prices as a bill with
  dotted leaders, a week view as a printed timetable, a status as a stamp.
- Pick one physical law and apply it everywhere. Examples: "everything sits on a ruled line",
  "everything is pinned", "nothing stands straight".
- Keep it from eating the story. Mid-project test: would someone who sees only the screen know
  what this product is? If the language became the subject, tone it down.
- Working tools need a quieter language (a spec sheet, a ledger, a timetable). It still needs a
  name and locked tokens.

## 3. Catalogue

Format: **Name.** Type / colour / layout / details. The type lines describe a kind of face, not
a named font. Pick the face with `typography.md`.

1. **Railway signage.** Neo-grotesk, white on one solid signal colour / strict grid, flush
   left, pictograms / flat fills.
2. **Technical reference manual.** Serif body with mono or pixel headings / off-white with line
   work in one ink / an essay column beside figures / figure numbers, ruler marks in the margin.
3. **Risograph zine.** Typewriter body / 2 spot inks with overprint / loose, stapled-page feel /
   grain, slight misregistration.
4. **Wine list or bistro menu.** Serif small caps / paper and one ink / centred columns / dotted
   leaders, tabular numbers.
5. **Theatre programme.** Huge condensed display with a tiny mono cast list / black on white /
   the page runs in acts / extreme size contrast.
6. **Type specimen tray.** One huge glyph per tile, tiny caps labels / grey tiles / an uneven
   tile grid that works as navigation.
7. **Library card catalogue.** Typewriter face / manila tones / ruled index cards / call numbers,
   stamped dates.
8. **Spec sheet.** All mono / black or off-white, no accent / a hairline table grid. Good for
   dashboards.
9. **Exhibition wall.** Quiet sans for wall labels / the works supply the colour / a horizontal
   strip at real proportions / small label captions.
10. **Shop sign plus notebook.** Grotesk headline with a handwritten second voice / one band of
    primary colour / a manifesto block / margin notes.
11. **Periodical archive.** Plain sans plus a serif / a pastel ground / one cover per screen,
    large issue numbers in the corners / a count such as "All (187)".
12. **Spreadsheet.** Plain sans in cells / grey UI / rows, row numbers, sortable columns as
    navigation.
13. **Field guide.** Botanical serif, italic Latin labels / muted green and paper / specimen
    plates with captions.
14. **Almanac or weather instrument.** Mono readings / dials and tables / one live data hook.
15. **Documentary title card.** Condensed caps pinned to the edges / dark, over film stills / a
    long chapter index.
16. **Departure board.** Mono caps in cells / black and yellow / board rows for lists and
    schedules.
17. **Receipt or packing slip.** Thermal-print mono / off-white, one ink / a narrow column /
    perforation lines.
18. **Blueprint.** Monoline technical face / white lines on deep blue / title-block corners,
    dimension callouts.
19. **Letterpress broadside.** Wood-type display / 2 colours at most / centred stacks / uneven
    ink.
20. **School exercise book.** Handwriting face with a plain text face / ruled lines, a red margin
    / stamps for emphasis.
21. **Object in a grey room.** Wide-tracked caps / a mid-grey void / one object, almost no text.
22. **Contact sheet.** Mono frame numbers / a frame grid / grease-pencil circles.
23. **Notice board.** Bureaucratic sans / pinned sheets at slight angles / stamps and dates.
24. **Ordnance map.** Map-label sans, italic serif for water / muted greens and browns / a legend
    as navigation / contour lines.

## 4. What strong examples share (use as checks)

1. One metaphor with a name.
2. A hard size ratio. Poster pages go to 8x or more. Template pages sit near 3x.
3. One or two faces, at least one not a default.
4. One loud colour, or none (photos supply the colour).
5. A utility face carries metadata: dates, numbers, labels.
6. The hero is the real thing: the room, the object, the product, the diagram. Not a stock photo
   with a headline.
7. UI words in the product's own voice ("We are open until 22:00"), not "Get started".
8. Navigation can be content: a list, an index, a table.
9. At most one live or physical hook (an open-now line, today marked in a week view).
10. An asymmetric grid instead of 3 equal cards, with a reason from the language.
11. A content number becomes a typographic element.
12. No gradients, glass, glow or icon rows.

## 5. Interaction that means something

Motion and interaction follow the language and the content. Examples: an open-now line computed
in the business time zone, today marked in a week view, a draggable photo rail, a reserve button
that shows the conditions first. No games or moving decoration unless the idea sentence asks
for it.

## 6. Where to look for references

Curated web design galleries, type sites that show faces in use, and printed objects from the
subject itself. Sites change, so check a reference before you show it to a user. Take structure,
proportion and rhythm. Never copy text, images or logos.
